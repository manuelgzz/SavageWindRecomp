# ROG Xbox Ally X: RADV artifact test build

This branch starts at upstream `test` commit
`0e21a86f9855ca4875d0f504dc30ffc81ecfca6b`. It includes the existing upstream
rendering corrections in
[`19f76b4`](https://github.com/Revivedx/SavageWindRecomp/commit/19f76b4ee857cacc9a0138eb241249f535681fc3):

- AMD/Intel texture-gather coordinate rounding compensation. This addresses
  shadow-edge dashes caused by rounding differences from Maxwell.
- Rendering into compressed textures at nonzero mip levels, array layers, and
  3D slices. Previously, the 32x32x32 BC4 volume generated by the game was
  excluded from those passes.

The supplied Alpha 4.1 logs (`428d9ccd`, Mesa RADV 26.2.6, Radeon 890M) show
`texture #3061 (nvn fmt 0x49, 32x32x32 target 2) can't be drawn into as format 95`.
They also confirm 1080p SMAA and a successful test with GPU overlap disabled.
The player reports the artifacts persist at both 30 and 60 FPS and with overlap
disabled. The volume fix directly addresses that warning; whether it fixes the
visible blue terrain/ruin patches still needs testing on the Ally. The gather
fix is also relevant, but is not proof of the cause of those patches.

These are upstream changes, not newly authored renderer fixes. This branch
contains other development changes from `test` and is not an official release.

## Build and download

The **Ally X Linux AppImage** GitHub Actions workflow builds an x86-64 AppImage
on pushes to this branch. After a successful run, download the
`SavageWind-ally-x-linux-x86_64` artifact from the run summary and extract it.
It includes `SOURCE_COMMIT.txt` and `SHA256SUMS` so the build can be identified.
The artifact contains the application and build tools, not game files or
generated game code.

Alternatively, from this branch on Linux with Podman installed:

```sh
make appimage ARCH=x86_64
```

The result is in `build/dist/`. Build instructions and dependencies are in
[linux.md](linux.md).

## Test without changing the existing installation

1. Close the game. Back up the existing Savage Wind data folder, especially
   `save/` and `savagewind.ini`. Use a separate copy of the data folder for this
   development build: set `SAVAGEWIND_DATA_ROOT` to its absolute path when
   launching. See [data-folder.md](data-folder.md). The development build may
   request rebuilding game code from your own local files.
2. Keep the old AppImage. Add this AppImage as a separate non-Steam game;
   do not force Proton. Remove the `SAVAGEWIND_GPU_OVERLAP=0` test option.
3. Use 1920x1080, 60 FPS, upscaler off, SMAA, original texture filtering,
   Console shadows, original draw distance, and frame generation off. Do not
   change driver or graphics settings during the comparison.
4. Revisit the same point near the Temple of Time at a similar in-game time.
   Compare a stationary view and a slow camera rotation against Alpha 4.1.
5. Keep the startup log immediately after testing. Verify its commit identifies
   this branch's build, and check whether the compressed-volume warning is gone.
   Its absence alone does not establish that every visible artifact is fixed.

The rendering fixes are enabled by default. For separate A/B tests with this
new build, disable only one at a time in Steam launch options:

```sh
SAVAGEWIND_VK_GATHER_BIAS=0 %command%
```

```sh
SAVAGEWIND_VK_BLOCK_ALL=0 %command%
```

Remove the option after each comparison. These switches are environment
variables, not INI keys, and the Alpha 4.1 binary does not contain these fixes.
Do not delete caches or saves to perform this test. To roll back, close the
development build and launch the old AppImage with its original data folder.

## Validation status

Upstream reports checking the rendering changes on RTX 3060 and Steam Deck
RADV without new validation messages. This does not substitute for testing the
reported visual defect on the ROG Xbox Ally X. A successful Actions build
verifies compilation and packaging only, not gameplay or artifact removal.
